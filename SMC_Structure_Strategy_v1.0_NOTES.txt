================================================================================
THE TWO RULES
================================================================================
Both fire on a MAIN-tier CHOCH on the 1m chart, confirmed on bar close.

RULE 2 - checked first, takes priority
    Condition: the 15m MAIN trend AGREES with the 1m CHOCH direction.
    Entry:     a limit on the pivot the CHOCH candle just broke.
    For a bullish CHOCH that pivot sits below price, so the buy limit is valid.

RULE 1 - the default
    Condition: the 15m trend does NOT agree. Counter-trend, deliberately.
    Entry:     a limit at a percentage pullback, default 50%.
    The leg is measured the way your 50% line measures it - from the live CHOCH*
    level up to the running extreme - using the engine's own f_retLvl(). It
    RATCHETS: each new high moves the level up and the resting order is
    re-placed, a down candle leaves it alone.

STOP        the live CHOCH* level, plus an optional buffer. florS.price - buffer
            for a long, ceilS.price + buffer for a short.
            While the order is still RESTING the stop follows that level as the
            engine moves it. It LOCKS at the moment of fill and does not move
            again.
TARGET      an R multiple of the entry-to-stop distance. Default 1.0.
SIZE        three modes, default risk-based off the stop so every trade loses
            the same cash if stopped - which is what makes the R target mean the
            same thing on every trade. Fixed quantity and fixed cash also there.

SESSION, all three as inputs, timezone Asia/Kolkata by default
    entries taken       06:00 to 23:00
    force flat          02:00, at market, target hit or not
An open trade is NOT closed at 23:00 - only new entries stop and resting orders
are cancelled.

================================================================================
THE ONE THING THAT COULD NOT BE BUILT AS ASKED
================================================================================
You asked that when a trade is running and the opposite CHOCH fires, the new
trade be taken AS WELL. A Pine strategy holds ONE net position. There is no way
to run a long and a short side by side, each with its own stop and target - if
you are long and then enter short, TradingView closes the long. That is the
engine, not a setting.

So the switch "Opposite CHOCH while in a trade: close and reverse" does the
closest thing: closes the running trade at market and opens the new one. Turn it
off and the new CHOCH is ignored until the current trade finishes.

In practice this rarely fires at all. The stop IS the CHOCH* level, and an
opposite CHOCH is by definition a close beyond that level - so the trade is
normally stopped out before the opposite CHOCH can print. It only survives when
the stop buffer is wide enough to sit outside the break.

================================================================================
TWO BUGS FOUND AND FIXED BEFORE RELEASE
================================================================================
The state machine was replayed outside Pine over 720,000 simulated bars with
4,978 fills, checking five invariants on every bar. The first pass found two
real faults, both mine:

1. A STALE SETUP COULD FIRE AFTER A TRADE CLOSED.
   A CHOCH in the SAME direction as a running trade still armed a new setup. No
   order could be placed while the position was open, so it sat there - and the
   instant the trade closed on its stop or target, that stale setup placed an
   order at a level that was by then minutes old.
   FIX: a setup is only accepted when flat, or when it is the opposite CHOCH the
   reverse switch is deliberately acting on.

2. THE STOP COULD END UP ON THE WRONG SIDE OF A RESTING ENTRY.
   Because the pending stop follows the live CHOCH* level, that level can be
   re-anchored upward past a resting rule-2 limit. The sanity check caught it and
   declined to re-place the order - but the order already resting stayed live, so
   it could fill with the stop ABOVE the entry.
   FIX: when the check fails, the resting order is cancelled and the setup
   dropped. It waits for the next CHOCH.

Second pass over the same 720,000 bars: ZERO violations of any of the five
invariants - never both sides resting, never a pending setup surviving a fill,
never in a position without a locked stop, and the bracket always on the correct
side of the fill price for both directions.

================================================================================
BACKTEST REALISM - PLEASE READ
================================================================================
When one 1m bar's range covers BOTH your stop and your target, TradingView
cannot know which came first and assumes the worst case - the stop. On a 1m
chart with 1:1 targets that will happen often, so the reported win rate is
PESSIMISTIC, not optimistic.

Turn on Bar Magnifier in the strategy's Properties tab (paid plans) and it
resolves the order from lower-timeframe data. Also set realistic Commission and
Slippage there before believing any equity curve - both default to zero and zero
is never true.

The 15m trend is read from CONFIRMED 15m bars only, so it updates once every 15
minutes on a 1m chart. That is correct and non-repainting, not lag.
